A separate PostgreSQL 16.10 rehearsal copied terminal command and event payloads from the serial cancellation fixture into **125,000 additional rows per table**. Of these, 4,096 per table were older than the retention horizon. The tables and indexes occupied 168 MiB and 102 MiB respectively. After ANALYZE, EXPLAIN (ANALYZE, BUFFERS) inside rollback-only transactions selected 128 each via `command_retention` and `event_retention`, then deleted via input/primary-key indexes. The local samples took 1.893 ms and 0.855 ms. The rehearsal used one universe and no competing production traffic. Runtime plans, lock waits, eligible arrival rates and actual disk growth require observation after separately authorized activation.

The real Accounts–Orbit–bot acceptance and the same-cutoff historical report reconciliation remain integration and deployment gates. Local tests used a dedicated disposable Compose database. No production SQL, backfill or cleanup was run.
